# Обучение SmolVLA на демонстрациях SO101E

## Что уже записывается

`hardware.py` использует плагины SO101E leader/follower. Это семь приводов:
`shoulder_pan`, `shoulder_lift`, `elbow_flex`, `wrist_flex`, `wrist_roll`,
`gripper`, `elbow_rotate` — именно в таком порядке. Значения передаются как
`.pos` в представлении драйвера. Их нельзя автоматически считать радианами
или градусами: реализация плагинов и файлы калибровки здесь не приложены.

В каждом шаге сначала читается фактическое положение follower
(`observation.state`), затем положение leader и отправляется команда follower.
В `action` сохраняется результат `send_action`, то есть эффективная отправленная
цель, а не фактическое будущее положение. Это обучение по демонстрациям:
модель учится предсказывать команды по изображению, текущему состоянию и тексту.

`capture.py` сохраняет RGB-видео `observation.images.front` размером 1280×720.
Камера запрашивается на 30 Гц, цикл управления и датасет работают на 20 Гц.
Это заданные частоты; реальный темп нужно проверять по `capture_timing.jsonl`.
Время камеры — момент получения кадра программой, а не аппаратная экспозиция.
Кадры камеры могут повторяться. Скрипт подготовки показывает число повторов
и наибольший интервал между шагами, но не выполняет временную интерполяцию.

Один старт/стоп — отдельный одноэпизодный LeRobot-датасет. Рядом лежит
`<id>.capture.json`: сторона подхода, калибровки, версии библиотек, статус.
Файлы надо переносить вместе с каталогами. Сохранённый абсолютный путь Jetson
не используется: подготовка ищет каталог рядом с JSON.

Возврат в home не включается в демонстрации. Текст `task` в исходных данных
пустой. `approach_side=left/right/top` — сторона подхода относительно камеры,
а не место назначения и не разметка предмета.

По описанию владельца задача — захватить предмет и перенести на другой объект
справа либо слева. Определять направление переноса по `approach_side` нельзя.
Нужен просмотр демонстраций и явная подпись каждого выбранного эпизода.
Сторона захвата добавляется к этой подписи автоматически из `approach_side`:
`top` → `Approach the object from above.`, `left/right` → подход слева/справа
относительно фиксированной камеры. Это значение подтверждено владельцем.
Если предметы различаются, указывайте, какой предмет и на какой объект переносить.
Пустую подпись или неверную подпись нельзя исправить настройками обучения.

## Официальный код и границы адаптации

- [Программа обучения LeRobot](https://github.com/huggingface/lerobot/blob/main/src/lerobot/scripts/lerobot_train.py)
- [Пример дообучения SmolVLA в исходниках](https://github.com/huggingface/lerobot/blob/main/src/lerobot/policies/smolvla/modeling_smolvla.py)
- [Описание SmolVLA](https://huggingface.co/docs/lerobot/smolvla)
- [Конфигурация модели](https://github.com/huggingface/lerobot/blob/main/src/lerobot/policies/smolvla/configuration_smolvla.py)

В `train_smolvla.py` адаптирован официальный пример с `policy.path=lerobot/smolvla_base`.
Сам цикл PyTorch вызывается из установленного LeRobot. Полную копию тренера
не дублируем: она зависит от множества внутренних модулей той же версии LeRobot.
Сохранено уведомление об Apache 2.0 для адаптированного примера.

Сверено с `main` LeRobot, где `pyproject.toml` указывает версию 0.6.2 и Python >=3.12.
Идентификаторы проверенных файлов GitHub (blob SHA, не commit SHA):

- `lerobot_train.py`: см. актуальную ссылку выше; API запуска через Python-модуль;
- `configuration_smolvla.py`: `a6d612d2322c27b2ee0b0737922d2b9677b127fd`;
- `modeling_smolvla.py`: `bd30b7f08f7798a7c24b4c7ddc964970caa54160`;
- `lerobot_dataset.py`: `34cec9d193ea7576e0baedf2a874fe0c599897a5`.

Это проверка исходников, а не подтверждение наличия релиза 0.6.2 в PyPI
или совместимости неизвестного серверного окружения. Не обновляйте окружение
сбора на Jetson автоматически. Для обучения используйте отдельное окружение
на сервере RTX 4090; сначала сравните установленную версию с `versions.lerobot`
в capture JSON. Для иной версии API может потребоваться адаптация.
Нужны PyTorch с CUDA, зависимости SmolVLA и рабочий видеостек LeRobot/PyAV/FFmpeg.
Установка зависимостей этими скриптами не выполняется.

Схема камеры и семи суставов берётся из вашего датасета вместо схемы базового
чекпойнта. Внутренние проекции модели остаются 32-мерными: SmolVLA дополняет
короткие векторы внутри сети. Замена `max_action_dim` на 7 нарушила бы
совместимость с исходными весами. Преобразования для Aloha отключены.
USB-порты, leader, камеры и ROS для обучения не подключаются.

## Проверка окружения

Все команды ниже выполняются на сервере из корня клонированного MultiVla
в активированном окружении обучения. Они не содержат значений для замены,
если проект и данные расположены так, как описано ниже.

```bash
python --version
python -m pip show lerobot torch av
nvidia-smi
python -m lerobot.scripts.lerobot_train --help
```

Команды показывают версии, GPU и доступные параметры; зависимости и проект
не изменяют. Импорт Python может создать обычный служебный кеш `__pycache__`.
Для установленной версии сверяйте наличие `policy.path`, `policy.input_features`,
`policy.output_features`, `dataset.root` с выводом справки.
Версия Python из VS Code на Mac не определяет окружение сервера.

## 1. Проверить загруженные записи

Дождитесь окончания передачи данных. При стандартном расположении:

```bash
python smolvla/prepare_training.py --source ~/datasets/grasp_capture
```

Это просмотр без создания датасета. Скрипт проверяет JSON-метаданные,
порядок суставов, частоту, завершение записи и временной журнал.
`REJECT` означает, что запись нельзя автоматически включать: рядом будет причина.
Проверка не декодирует видео и не подтверждает успешность показанного действия.
Повторы кадров и большие интервалы требуют просмотра записи: универсальный
допустимый порог без анализа ваших движений не задан.

## 2. Подписать и выбрать демонстрации

Создайте вне Git файл `~/datasets/so101e_tasks.json` в формате JSON-объекта:
ключ — точный id записи, например имя каталога `so101e_..._left`,
значение — непустая текстовая инструкция, описывающая показанное действие.
Для переноса направо возможен текст
`Pick up the object and place it on the object on the right.`;
для переноса налево замените `right` на `left`, только если это соответствует видео.
Сторону захвата в этот текст дублировать не нужно: скрипт добавит её из capture JSON.
Не задавайте в подписи сторону захвата, противоречащую метаданным.
Английский текст — начальный вариант для эксперимента, не гарантия лучшего качества.
Русские команды голосового контура впоследствии потребуется согласовать с текстами
обучения; распознавание речи само по себе этим обучением не обучается.

Включайте только просмотренные успешные записи. Эпизоды, не перечисленные
в JSON, не попадут в обучение. Ошибочные и demo-записи отклоняются даже при
наличии подписи. Не смешивайте разные калибровки без отдельного разбора.

## 3. Собрать единый датасет

```bash
python smolvla/prepare_training.py --source ~/datasets/grasp_capture --labels ~/datasets/so101e_tasks.json --output ~/datasets/so101e_pick_place
```

Создаёт новый датасет `~/datasets/so101e_pick_place`; исходные записи не редактирует.
Если пути отличаются, замените значения `--source`, `--labels`, `--output`.
`local/so101e_pick_place` — локальный идентификатор, а не обязательный репозиторий
на Hugging Face. Публикации данных нет.

Программа последовательно читает кадры исходных датасетов через LeRobot,
добавляет подписи, сохраняет границы эпизодов и рассчитывает статистики штатным
writer LeRobot. Видео декодируется и кодируется заново в H.264: это требует времени,
свободного диска и может внести потери сжатия. Разрешение сохраняется, состояния
и команды не пересчитываются. Пересэмплирование реального времени не выполняется.
Это простой переносимый путь добавления task, а не побайтовое объединение MP4.

`training_sources.json` хранит происхождение эпизодов, подписи, калибровки и сводку
времени; исходные подробные журналы остаются в capture-каталогах.
При ошибке результат помечен незавершённым и не допускается к обучению.
Существующий выходной каталог не перезаписывается: для повтора задайте новый путь.

## 4. Проверить команду и выполнить короткий запуск

```bash
python smolvla/train_smolvla.py --dataset ~/datasets/so101e_pick_place --output ~/training_runs/so101e_smoke --steps 20 --save-freq 20 --num-workers 0
```

Без `--run` выводится только команда: модели не скачиваются, обучение не начинается.

```bash
python smolvla/train_smolvla.py --dataset ~/datasets/so101e_pick_place --output ~/training_runs/so101e_smoke --steps 20 --save-freq 20 --num-workers 0 --run
```

С `--run` запускается обучение на CUDA. При первом запуске скачиваются базовая
модель и связанные файлы в кеш Hugging Face; создаётся каталог результатов.
Публикация модели и внешние трекеры экспериментов отключены.
RTX 4090 указана владельцем; совместимость CUDA и доступная память ещё не проверены.

Успешный smoke-запуск подтверждает чтение видео, текстов и векторов и вычисление
градиентов. Он не подтверждает, что робот освоил действие.
При нехватке видеопамяти уменьшите `--batch-size` с 8 до 4 или 2.
Сначала устраните ошибки короткого запуска, затем начинайте длительный.

## 5. Начальный эксперимент обучения

```bash
python smolvla/train_smolvla.py --dataset ~/datasets/so101e_pick_place --output ~/training_runs/so101e_run01 --batch-size 8 --steps 20000 --save-freq 1000 --run
```

Создаёт новую папку результатов. Если меняете пути, подставьте свой датасет
и новый каталог запуска. 20 000 шагов и batch 8 — стартовые параметры,
а не рассчитанное по ещё не полученным данным оптимальное число шагов.
`steps` — число обновлений весов, а не число кадров или эпизодов.
По умолчанию SmolVLA предсказывает блок из 50 действий; при 20 Гц это 2,5 с.
При будущей настройке исполнения длину открытого выполнения блока нужно выбирать
отдельно. На роботе обучение ничего не запускает.

Чекпойнты сохраняются LeRobot в каталоге запуска, обычно
`checkpoints/last/pretrained_model`. Скрипт не реализует продолжение прерванного
запуска: для resume используйте штатный LeRobot с сохранённым train_config
после проверки параметров установленной версии.

Этот начальный запуск использует все выбранные эпизоды. Перед сравнением качества
нужно выделить целые демонстрации для проверки, а не случайные соседние кадры
одного движения: они слишком похожи. Низкий training loss означает лучшее
совпадение с демонстрациями, но не гарантирует захват и перенос на реальном роботе.
Данные ещё загружаются: число эпизодов, баланс направлений, качество видео
и реальная успешность демонстраций пока не проверены.

## Локальные проверки кода без оборудования

Из корня репозитория в обычном Python без PyTorch/LeRobot:

```bash
python -B -m unittest discover -s smolvla/tests -p test_training.py -v
```

Тесты используют временные файлы и не обращаются к аппаратуре.
Они проверяют защиту от demo/незавершённых записей, порядок суставов,
временные метки, явные task-подписи и параметры команды обучения.
Полноценную совместимость LeRobot/видео/CUDA подтверждает только smoke-запуск
на сервере с настоящими данными.
